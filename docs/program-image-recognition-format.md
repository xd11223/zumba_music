# ZIN／Mega Mix 圖片辨識固定格式

> 格式版本：`program-import-v1`
> 用途：將 ZIN 或 Mega Mix（MM）教材照片經 Codex 人工辨識後，輸出成固定、逐行且可由程式解析的文字。
> 第一階段不由 Telegram Bot 自動 OCR；Codex 只負責辨識與整理，正式建立教材前仍需人工確認。

## 1. 固定輸出格式

每次辨識結果都必須包含一個 `program-import-v1` code block：

```program-import-v1
FORMAT_VERSION: 1
TYPE: MM
ISSUE: 114
RELEASE_MONTH:
TITLE: Mega Mix 114

TRACKS:
01 | Song Name | Artist | 120 | 3:15 | Style
02 | Another Song |  |  |  |
```

## 2. 教材欄位

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `FORMAT_VERSION` | 是 | 目前固定為 `1` |
| `TYPE` | 是 | 只允許 `ZIN` 或 `MM` |
| `ISSUE` | 是 | 教材期數，例如 `124`、`114` |
| `RELEASE_MONTH` | 否 | 圖片明確顯示時填 `YYYY/MM`；未顯示時留空 |
| `TITLE` | 否 | 教材完整標題；只有期數時可填 `Mega Mix 114` 或 `ZIN 124` |

ZIN 與 MM 都一定要有 `ISSUE`。禁止從期數自行推測發行月份。

## 3. 歌曲欄位

每首歌曲一行，固定六欄：

```text
順序 | 歌名 | 歌手 | BPM | 時長 | 曲風／教材分類
```

規則：

- `順序`：兩位數，從 `01` 開始，依照片中的上下順序排列。
- `歌名`：必填，保留原始大小寫、重音符號與標點。
- `歌手`：圖片完整且清楚時才填寫。
- `BPM`：只填整數，不加 `BPM`。
- `時長`：使用 `M:SS`。
- `曲風／教材分類`：例如 `Merengue`、`Warm-up`、`Cooldown`；圖片未完整顯示時留空。
- 選填欄位無資料時保留空欄，不能刪除分隔符號。
- 欄位內容若本身包含 `|`，必須寫成 `\|`。

## 4. 圖片辨識規則

- 只記錄圖片中清楚可見的資訊。
- 被 `...` 截斷的文字不能自行補完。
- 截斷的歌手或曲風欄位留空，並記錄在 Markdown 的「待確認」區塊。
- 不保存評分、下載狀態、ZF、勾選圖示或其他 App 狀態。
- 多張圖片依內容上下順序合併。
- 多張圖片重疊出現同一首歌時只保留一次，並維持首次出現的正確順序。
- 如果兩張圖片對同一首歌的資料不同，列入「待確認」，不能自行覆蓋。
- 看不清楚歌名時，不建立猜測歌曲；使用 `UNKNOWN-01` 暫代並列入「待確認」。

## 5. 人工檢查摘要

每份辨識結果的 code block 後必須附上：

```markdown
## 待確認

- 發行月份未出現在圖片中。
- 第 3 首歌手文字被截斷，因此程式資料留空。
```

「待確認」是提供人閱讀的內容，不屬於程式匯入資料。

## 6. 建立教材前檢查

將資料交給 Bot 或匯入程式以前，必須確認：

- `TYPE` 正確。
- `ISSUE` 正確。
- 歌曲數量與照片一致。
- 歌曲順序與照片一致。
- 每首歌都有歌名。
- 沒有因多張圖片重疊而重複。
- 沒有把截斷文字當成完整資料。
- 所有「待確認」項目都已由人檢查或接受留空。

## 7. 給其他 Codex 的固定提示

```text
請依 docs/program-image-recognition-format.md 的 program-import-v1 格式辨識教材圖片。
只填圖片中清楚完整的資料，不猜測被省略號截斷的內容。多張圖片要依順序合併並去重。
辨識後建立 Markdown 檔，保留程式可讀 code block 與待確認清單；未經我確認不要寫入資料庫。
```
