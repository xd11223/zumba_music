# 0004. 模糊比對相似度閾值決策 (防誤判機制)

## 狀態
已接受 (Accepted)

## 上下文
我們決定採用「純後台字串相似度自動判定為同一首歌 (方案 A)」來處理拼寫細微差異。然而，若相似度閾值設得太低 (例如 85%)，可能會發生誤判。例如將 `Voltaje` 與 `Voltaje 2`，或是 `Boompala` 與 `Boompala Remix` 判定為同一首歌，導致換歌時系統判定「歌單無變動」而漏記。

我們需要在「處理打錯字與格式細微差異的容錯性」與「避免相似歌名誤判」之間取得平衡。

## 決策
我們決定將**字串模糊比對相似度閾值拉高至 95%**。

此決策採取 **方案 Y (寧缺勿濫)** 原則：
- **高相似度要求**：只允許處理括號被拿掉、全半角引號混用、極微小的拼寫打錯。
- **防止誤判**：若有加 `Remix`、`Radio Edit`、數字（如 `2`）或副標題等實質歌名變動，相似度計算結果會低於 **95%**，系統將一律視為「新歌」。

## 後果
- **優點**：
  - 幾乎零誤判風險。
  - 不需要實作複雜的「手動拆分」或「對話式按鈕確認」邏輯，保持 Bot 互動極簡。
- **缺點**：
  - 容錯率降低。若使用者打錯多個字母（相似度低於 95%），系統會建立新歌，可能導致重複。使用者需自行注意歌名拼寫。但在高精準度的要求下，此缺點是可接受的。
