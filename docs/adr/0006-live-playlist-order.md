# 0006. Live 歌單保留播放順序

## 狀態

已接受 (Accepted)

## 上下文

原 ADR 0005 將 Live 歌單視為無序集合，只記錄歌曲是否 active。2026-08 stakeholder 訪談確認，Live 歌單的播放順序具有實際業務意義：暖身歌曲通常位於歌單前段，收操歌曲通常位於後段。若只保存集合，Bot 顯示時無法還原老師實際安排。

Live 更新會由老師提供完整文字歌單，每行一首，行序可作為明確且穩定的順序來源。

## 決策

1. Live 完整文字歌單的行序就是更新後的播放順序。
2. 每個 active Live 項目保存從 1 開始的 `position`。
3. 更新時仍以集合差異判斷新增與移除，同時比較並更新所有保留歌曲的位置。
4. 只改變位置不建立新 `live_history`，也不填寫 `end_date`。
5. `/status` 與更新後預覽必須依 `position` 排列。
6. 同一首歌曲在一份 Live 歌單中只能出現一次；重複輸入必須在確認前處理。
7. 第一階段不保存每一天的完整順序快照，只保存目前 active 歌單順序。

## 後果

- **優點**：
  - Bot 能依老師安排顯示暖身、主要歌曲與收操的正確位置。
  - 重新排序不會污染歌曲使用歷史。
  - 完整文字輸入天然提供順序，不需要額外逐首設定。
- **缺點**：
  - 無法查詢歷史上任意一天的完整播放順序。
  - 每次 Live 更新需要同步更新 active 歌曲位置。
  - 若未來需要歷史順序，必須新增 playlist snapshot 類型的資料模型。
